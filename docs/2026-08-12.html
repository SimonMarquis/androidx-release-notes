Tracing

2.0.0

Major features of 2.0.0:

New in-process API enables:

  • Record trace content in-process, in the field
  • Perfetto flows (arrows from one slice to another)
  • Perfetto annotations (key/value slice metadata)
  • traceCoroutine() {} - Coroutine Tracing API which traces thread switches
  • Category filtering
  • Significantly lower overhead than existing android.os.Trace API and trace() {} wrapper
  • KMP tracing - can be used on libraries without Android dependency, and on host JVM projects
  • After the fact merging with System trace recording (implemented by default in AndroidX Benchmark 1.5)

Note that the new tracing APIs record to a process-controlled buffer which is not yet captured by Studio system trace recording. This will be addressed in the Studio Profilers in an upcoming release.

The existing android.os.Trace / trace() {} APIs have not been deprecated. These APIs are still recommended for low frequency events that should always be recorded into the system trace buffer, especially in libraries.

Wear Compose

1.7.0-beta01

The 1.7.0-beta01 release of Compose for Wear OS indicates that this release of the library is feature complete and the API is locked. Wear Compose 1.7.0-beta01 includes the following new functionality:

  • One-handed gesture support, consisting of gesture handlers for primary action (e.g. double-pinch) and dismiss action (e.g. wrist-turn) and animated indicators that show when the gestures are available on clickable UI elements (like buttons and cards), scrollable lists and pagers.

  • Introduced @FrequentlyChangingValue and @RememberInComposition annotations that provide lint warnings to prevent performance issues caused by reading high-frequency state updates or failing to remember objects during composition.

Webkit

1.17.0

Important Changes Since 1.16.0

  • Enhanced Navigation Capabilities (WebViewCompat#navigate): Introduces a modern replacement for WebView#loadUrl. Key capabilities include replacing history entries, returning a trackable Navigation object, and consistent header persistence during state save/restore.
  • HTTP Cache Quota Control (Profile#getHttpCache): Provides APIs to inspect and adjust profile-level HTTP cache quotas, benefiting static-content-heavy applications and reducing cache directory footprint when unused.
  • Preconnection Queueing (Profile#enqueuePreconnect): Allows enqueuing preconnect requests in advance without forcing an immediate startup WebView.
  • Favicon Download Optimization (WebSettingsCompat#setDownloadFaviconsEnabled): Enables apps to disable automatic Favicon fetching on navigation to reduce memory consumption and network bandwidth.
  • Prerender Management (Profile#getMaxPrerenders / clearMaxPrerenders): Introduces methods to retrieve and reset maximum allowed concurrent prerenders.
  • API Modernization & Cleanups: Deprecated SpeculativeLoadingParameters in favor of PrerenderParameters / PrefetchParameters. Removed experimental Profile#setOriginMatchedHeader (superseded by Profile#addCustomHeader in 1.15.0).
  • Proactive Crash Prevention Lint Rule: Adds an AndroidX lint check that flags missing onRenderProcessGone implementations when a custom WebViewClient is attached, encouraging developers to handle renderer crashes gracefully.
